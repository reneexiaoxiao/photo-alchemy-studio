# 从照片到风格：可迁移的视觉语法

原创工作流设计与文字：**Renee**，AI-assisted，MIT。

这套方法处理已经存在的照片。目的地、示例中的建筑、器物和颜色都属于样本；它们不是生成下一张图的默认内容。一张好看的示例只能说明一个方向，不能证明该方法适用于所有照片。

## 三层必须分开

1. **固定语法**：换照片后仍应看见的组织方法，例如五个主形的咬合、真实阴影边界的放大、沿轮廓改变方向的砖片。
2. **适配变量**：由输入决定的裁切、重心、横竖构图、颜色、密度、碎片数、层数和纹理分布。
3. **样本残留**：某次作品的拱门、渡轮、茶杯、地名、蓝白配色和装饰。这一层不能自动进入下一次作品。

固定语法通常约束“元素之间如何发生关系”，而不固定“画面里必须有什么”。材质只是其中一组方向；形态压缩、光影反转、轮廓展开、视觉呼应、跨视角连接和多中心叙事是不同的加工方法。

## 每次输入的最小观察记录

实际打开每张输入图，记录以下内容即可，不把观察表印在作品上：

- **身份锚点**：2–4 个足以指回原图的可见特征及关系；优先轮廓、数量、相对位置、朝向、负形和特殊色块。不能只写“建筑”“好看的风景”。
- **视觉骨架**：主轴、水平/斜向/环形走势，遮挡层次，明暗边界，主体和空白的比例。
- **细节职责**：哪些细节承担识别，哪些只制造杂乱。删减后若仍能认出主体，可以去掉后一类。
- **源色关系**：最主要的明暗和冷暖关系、一个可用强调色；没有明确强调色时不要硬加。黑白照片可继续黑白。
- **输入约束**：单/多主体、人物或宠物身份要求、可否重画、是否必须保留原字或原像素。

目的地只在用户给出真实地点或希望探索相关文化线索时提供背景，不能替代以上观察，也不参与适配评分。

## 从观察到可执行的提示词

先决定当前照片采用哪条构图分支，再填写该风格的提示词。提示词必须包含具体输入锚点、固定语法、这张图采用的变量和禁止新增的内容。不能只说“做成这个风格”，也不能把示例场景写进提示词。

默认交付一张完整作品。优先保留原始长宽比；只有构图分支明显受益时才调整裁切，且不裁掉锚点。用户明确要求分享尺寸时服从该尺寸，通过重组留白适应，不能靠补造景物扩图。文字默认不加；只使用用户指定、已核对的短文字。

把实际输入照片作为图像工具的编辑目标传入，而非只把它描述成文字。使用 `referenced_image_paths` 或合适的会话图像引用；缺图时索要缺失输入，不能拿图鉴样本顶替。示例图作为风格参考时，明确标明“只取语法，禁止取其主体、配色和地理符号”。

## 重画、混合与身份保留

- `redraw`：以输入为依据重新构造整张图，保留语义和结构锚点；不承诺人物长相、产品细部、原字或原像素完全一致。
- `hybrid`：将摄影感片段与抽象形态或重组版式结合；该字段描述视觉方法，也不等于像素级保留。当前使用整图生成时仍须检查片段漂移。
- 必须保留原像素、精确人脸或真实文字时，先选择已有的照片保留工作流，并确认实际工具能够保留；不能把本套重画结果称为无损编辑。
- 人物可在用户允许时作为姿态、剪影或尺度线索；不得自动把近景肖像变成另一张脸。宠物须保留体形、耳形、毛色块和朝向；若这些特征一经简化就丢失，应改选摄影保留方向。

## 用三种不同输入检查迁移

一次风格测试至少区分：风格概念图、单图转译样例、跨输入迁移试作、已在用户真实照片上验证。只有确实完成相应步骤，才更新对应状态。

迁移试作可取三种结构显著不同的实际输入，例如：建筑空间、单个食物/器物、植物/宠物或自然地貌。它们不必同地点、同色系、同长宽比，也不必全部来自用户；合成源照片应清楚标注。固定风格语法不变，锚点、构图与调色必须随输入变化。不能先分别生成漂亮的地方主题图，再称为照片迁移验证。

比较原图和结果，按事实记录：

| 检查 | 可以支持的判断 | 失败信号 |
|---|---|---|
| 来源联系 | 指出至少两个仍存在的独特锚点和一个关系 | 只能认出大类，换一张同类照片也一样 |
| 风格辨识 | 三张结果都出现同一固定语法 | 只统一纸纹、颜色或景点 |
| 适配变化 | 各输入采用合理的构图、密度、色彩或尺度变化 | 三张都套同一场景、同一色盘或同一中心模板 |
| 加工价值 | 删减、提炼或关系重组带来明确视觉重点 | 原照叠纹理，或完全换成另一处风景 |
| 可分享性 | 缩略图先看见主形，近看有值得看的细节 | 层级平均、装饰过量、识别细节被压没 |

不捏造通用分数、成功率或用户偏好。一次主要失败最多做一次针对性纠正；继续失败时展示限制并换方法，不把无限重试当成风格稳定。

## 推荐数据的含义

`style-contracts.json` 记录执行前的结构判断，不是质量评分：`bestFeatures` 表示加分线索，`needsAny` 是至少需要其中一个的输入条件，`avoidFeatures` 表示当前方式不应自动选择的条件。空 `needsAny` 表示不强制某一结构，不代表对所有照片都有相同表现。`inputCount` 是一次作品接受的照片数；一张包含多个可用细节的照片可以支持叙事方法。

## 借鉴与署名边界

本次抽象方法受到已纳入库中的社区工作流启发：Minimal Zine 的固定规则/可变规则/样本残留，Photo Revival 对识别细节的压缩，Visual Memory 的原图重新生成与版式选择，以及 Photo Relic 的来源形态线索。各原始模块仍保留原作者和许可。这里的 11 个原创模块分别建立自己的变换规则，没有把上游独有构图或文字换名当作原创。Renee 的署名指向本项目工作流设计和文字，不主张发明刺绣、版画、彩玻璃等传统媒介。

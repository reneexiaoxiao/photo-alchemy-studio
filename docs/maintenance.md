# 维护风格库

## 平时收集

本地 HTML 的“添加风格”支持名称搜索和 GitHub 仓库链接。来源选定后，服务读取许可证、具体 SKILL.md 与依赖文件；通过校验后按固定提交安装到 `.local/extensions/`，更新 `.local/catalog.json`。目录显示作者、来源与许可，复制出的指令直接指向该入口。

本地扩充不会自动同步到 GitHub。`.local/`、照片、凭据和历史版本均排除在 Git 之外。需要公开分享新风格时，在 Codex 里明确说“把这个风格纳入公开库”，核对再分发权与素材授权后再放进 `community/`、补原许可证和来源条目。

名称匹配不确定时让用户选择候选；许可证缺失、非商业限制、需要执行额外安装脚本或跨目录依赖的来源，交给 Codex 按具体情况处理。不要为了安装成功改写原许可或将缺失材料标成已安装。

## 更新与恢复

- 点击“检查已安装风格更新”只读取上游版本，不覆盖现有内容。
- 选择“查看新版本”，重新核对许可和内容，再安装。相同版本且文件完整时不会重复安装。
- 升级时旧文件和原目录条目保存到 `.local/history/<id>/<time>/`。恢复前停服务，对照该目录下 `style.json` 与 `extension/`，用旧版替换对应扩充目录和索引条目，再启动并回读。不要只恢复文案而遗漏引用资源。
- 备份整个 `.local/` 能保留扩充和升级历史，但它是个人材料，不用于公开提交。

## 增加原创风格

在 `styles/` 新增一份聚焦具体媒介的 `.md`，写清选图条件、不可变的场景事实、材质结构、提示词骨架和失败判断。在 `originals.json` 增加条目，使用内置图片工具制作有来源记录的样张，不用滤镜截图假装完成新风格。先看 1–2 张代表图，再按实际问题改进。

运行 `python3 scripts/build_catalog.py` 同步生成 `catalog.json` 和 `catalog.js`；网页数据不手工维护两份。社区条目来自 `community-catalog.json`。

## 公开发布

1. 只提交原创文件和明确可再分发的社区代码/文档；图像另核实授权。保留每个源的 LICENSE、NOTICE 和版本。
2. 更新 `THIRD_PARTY.md`、`docs/source-audit.json` 和相应目录；不把别人的内容标成原创。
3. 跑测试和目录校验，在浏览器检查搜索、复制、添加、错误恢复与窄屏。
4. 检查 Git 差异与即将公开的文件，不包含本地照片、绝对私有路径、凭据或 `.local/`。
5. 推送之后从公开地址回读仓库；本地完成不等于线上已发布。

## 模型升级

默认保留表现稳定的源方法。只修复真实失败：例如纸雕生成成石雕，就明确平面卡纸、开窗与层间距；版画仍像调色照片，就先要求简化大色块，再加纹理。记录具体输入、输出、问题与修改效果。工具未提供型号元数据时只记工具名，不能把用户期望的型号写成实测事实。

当前维护是按需操作，没有安装后台任务或定时自动升级。
